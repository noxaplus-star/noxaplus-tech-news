# Customization guide

This guide covers the parts you are most likely to change: brand, content, artwork, colours, typography, and routing. Everything is static; there is no build step.

Before publishing a customised copy, run `node scripts/check.mjs`.

---

## 1. Brand, credits, and contact details

The canonical identity lives in `SITE` inside [`assets/data/news.js`](../assets/data/news.js):

```js
var SITE = {
  name: 'NoxaPlus Tech News',
  shortName: 'NoxaPlus',
  developer: 'NoxaPlus',
  website: 'https://www.noxaplus.ir',
  email: 'NoxaPlus2025@gmail.com',
  phone: '09198690446',
  url: 'https://noxaplus-star.github.io/noxaplus-tech-news/'
};
```

Change `name`, `shortName`, `url`, and contact fields first. `url` is used for canonicals, Open Graph URLs, JSON-LD, sitemap, and the feed, so it must be the final public URL with a trailing slash.

The wordmark is rendered by `headerHTML()` and `footerHTML()` in `app.js` (`brand-name` + `brand-sub`). The logo mark is the inline `logoSVG()` function, with matching source files in `assets/icons/`. Replace the three SVG files and re-run `node scripts/render.mjs` to regenerate the PNG icons and social cards.

The About page, page titles, `manifest.webmanifest`, `LICENSE`, and `README.md` also carry the project name. Update them together, then run the validator.

## 2. Editorial content

All stories, desks, and bylines live in `news.js`. The schema is documented in the README. Two rules matter most:

- `ARTICLES` must stay sorted newest first; the validator enforces unique, descending dates.
- Every human-readable field is an `{ en, fa }` object. Lists (tags, takeaways, list blocks) use `{ en: [], fa: [] }`.

To add a desk, append an entry to `CATEGORIES` with a unique lowercase `id`, English and Persian names, a description, a strong `color`, and a translucent `soft` colour. Navigation, chips, footer links, JSON-LD, and the sitemap pick it up automatically after regeneration. The front-page grid expects at least three featured and four trending stories; update those flags in the data.

To remove the demo disclosure, update the footer, the About page (`renderAbout()`), and the notices in the README and changelog. Do not remove it while the content is still fictional.

## 3. Covers

Covers are deterministic 1200 × 675 SVGs generated by [`scripts/covers.mjs`](../scripts/covers.mjs). Each entry maps a slug to a palette and a motif:

```js
['ai-small-models', 'small-models-big-shift', 'ai', 'small']
```

Available motifs: `small`, `network`, `bars`, `orbits`, `keyhole`, `lattice`, `constellation`, `moon`, `stack`, `monolith`, `exploded`, `die`. Run:

```bash
node scripts/covers.mjs
```

To use photography instead, put your images in `assets/covers/` and point each story's `cover` field at them. Keep a 16:9 ratio; `storyCard()` and the article figure set width and height to 1200 × 675.

## 4. Social cards

`scripts/render.mjs` uses headless Chrome or Edge to render a 1200 × 630 card for the default share image and every story, using the story's title, deck, desk colour, and cover. Update the copy in the template function, then run:

```bash
node scripts/render.mjs
```

The script finds Chrome at the standard Windows paths. On macOS/Linux, add your browser path to the `CHROME` array. The generated files are `assets/og/default.png` and `assets/og/<slug>.png`; `pageMeta()` references them automatically.

## 5. Colours and themes

Design tokens live at the top of [`style.css`](../style.css):

```css
:root {
  --bg: #f4f1e8;
  --surface: #fbf9f2;
  --ink: #12130f;
  --accent: #d8ff3e;
  --accent-2: #2b4bff;
}
[data-theme='dark'] {
  --bg: #0e100c;
  --ink: #f2f0e4;
}
```

Keep `--accent-ink` readable on `--accent`. Desk colours are separate: `--cat` and `--cat-soft` are defined per `.cat-*` class, with brighter variants for dark mode. Components that must stay dark regardless of theme (top bar, footer, ink panels, developer card) intentionally redefine local palette variables; preserve that pattern when adding similar components.

Also update `<meta name="theme-color">` in every HTML shell (the light value) and the manifest's `background_color` / `theme_color`. `app.js` updates the meta tag at runtime for dark mode.

## 6. Typography

Fonts are self-hosted in `assets/fonts/` and declared with `@font-face` at the top of `style.css`:

- Newsreader — display serif, roman and italic,
- Inter — interface and body,
- Vazirmatn — Persian.

To swap a typeface, replace the WOFF2 files, update the `@font-face` blocks, and adjust `--font-display`, `--font-body`, and `--font-fa`. Do not add Google Fonts or another CDN; the project promises zero third-party runtime requests.

## 7. Interface copy and languages

Interface strings are in the `UI` object in `app.js`. Each key has `en` and `fa` values and is read through `t('key')`. For one-off bilingual strings, use `bi('English', 'فارسی')`.

Adding a third language is a larger change: extend the language state and toggle, add a branch to `t()`, add a field to every content object, extend date/number formatting, and update the `<html dir>` logic. If the language is LTR, the layout work is mostly formatting; an RTL language needs a review of every flex/grid order and icon direction.

## 8. Routing and page shells

Each page is a thin shell with `<body data-page="…">` and mounts for `#site-header`, `#page`, and `#site-footer`. `pageHTML()` switches on `data-page`; `article.html` and `category.html` read `slug` and `c` from the query string. To add a page:

1. Copy an existing shell and set a new `data-page`.
2. Add a `case` in `pageHTML()` and a renderer.
3. Add metadata in `pageMeta()`.
4. Link it from the header or footer.
5. Add it to the sitemap generator and the service-worker shell list if it should work offline.

## 9. Local storage keys

- `noxa_lang` — `en` or `fa`
- `noxa_theme` — `light` or `dark`
- `noxa_bookmarks` — JSON array of slugs
- `noxa_newsletter` — JSON object for the demo form

Rename the keys only with a migration plan; changing them resets visitor preferences.

## 10. Offline cache and feeds

After changing CSS, JS, data, fonts, or covers, bump `VERSION` in `sw.js` (for example `noxa-news-v3`) so clients replace the precache. Static assets use stale-while-revalidate, so a version bump is the reliable way to force a clean update.

Regenerate feeds and the sitemap whenever content or categories change:

```bash
node scripts/feeds.mjs
node scripts/check.mjs
```

## 11. Configuration checklist

- [ ] `SITE` name, URL, email, phone, website updated.
- [ ] All twelve stories replaced or clearly marked as samples.
- [ ] Covers and social cards regenerated.
- [ ] Theme colour, manifest colours, and icons match the new brand.
- [ ] Feeds and sitemap regenerated.
- [ ] Service-worker version bumped.
- [ ] `LICENSE`, README, and About credits updated.
- [ ] `node scripts/check.mjs` passes in both languages, light and dark.
